# 旧セーブ移行処理の削除実施計画

対象は [DEV-088の調査報告書](LEGACY_SAVE_AUDIT.md) に続く **DEV-089**。本資料の作成時点ではコード・テスト・形式・表示版・配信ファイルに変更なし。ユーザーの別途指示を受けて、以下の Phase 4〜6 を開始する。ここでの Phase は本作業内の段階であり、ゲーム全体のロードマップとは独立する。

## 開始条件と受理方針

- 最新の `main` と `AGENTS.md` を確認し、監査基準、現行ライター、復元関数、テストの差分を確認する。調査時の形式は12。現行JSONの出力構造を維持できる場合は形式番号を据え置き、入口を `data.version === version` に統一する。壊れた入力・旧版・将来版は通常の復元検証で拒否する。バージョン番号変更とブラウザのDBスキーマ変更は別の判断。
- 形式12の中でも、ver.50の個体数が512を超える保存はver.51のデコーダーで既に拒否される。現在の枠を丸ごと受理または拒否し、削減・補正・自動削除は導入しない。形式12の旧データで検証を通過できるものは、現行12と同じ条件で復元する方針を推奨。ゲーム版を区別できる情報がないため、ver.50由来だけを正確に選別することはできない。形式12を一律に拒否する場合はver.51の正常な枠も失うため、別の明示判断を要する。
- LS-D01の判断基準は、現行ライターの出力であることを実際の初期・進行中・JSON往復データで確認できるか。探索・商店在庫の欠損を拒否する場合は正規の現行出力が両方を持つと確認し、欠損拒否のテストを付ける。住民の明示null、HP/クールダウンの正当な省略、装備なし戦利品は維持。採集中のnull予約と負残高は互換由来と現行の使われ方を分離して評価し、立証できなければ今回は維持する。セーブ結果の経済値を無断で補正しない。
- ユーザーには後続作業の開始指示に加え、上記の同一形式12の扱いを確認する。完成後も開発途中の旧データを引き継ぐ前提は置かない。正式版同士の互換性は別の論点とする。

## Phase 5　回帰検証とユーザーへの案内

1. 形式12の現在のライター出力をJSON経由・IndexedDB経由で往復する。開始直後、冒険中、洞窟の再出現待ち、探索済み／未探索、野外MOBが負傷・逃走・狩猟中、採取途中、枯渇と回復、建築中、住民戦死後・作業中・徘徊中、在庫不足・国庫0G・収支を代表ケースにする。時刻・次回イベント・個体ID・在庫予約を照合する。
2. 1〜11、未知版、異なるformat、壊れた現行データからの失敗を確認。形式12の旧高密度ケースは現行の512件上限に従うことを確認する。JSON取込時は検証失敗が枠書き込みより前、キャンセルは状態と枠のどちらにも影響しないことを確認。
3. `node --test tests/*.mjs` を全件実施し、基準の28件からID・カバレッジの差を説明する。ブラウザで未保存からの新規開始、手動セーブと起動／手動ロード、宿泊・洞窟往復の自動保存、JSON入出力、削除の取消と確定、失敗時に既存スロットの保持を確認する。ブラウザ試験はユーザーの実データを使わず専用プロファイルで実施。
4. 非対応の枠は起動・手動・取り込みで復元しない。現行の起動失敗は通知後に新規状態で進み、削除は行わない。進める場合は、「旧データを残すなら先にJSON書き出し → 左上の詳細 → セーブ → セーブデータ削除 → 確認 → 再保存前にページを再読み込み」を案内する。通常のオートセーブ・手動保存は枠を上書きするので、退避する場合は宿泊・エリア切替などの保存操作より前に行う。受理可能と確認できた現行セーブには削除を要請しない。

## Phase 6　資料・公開と完了条件

- 現行仕様書 CUR-SYS-004を中心に、実コードとの差（個体上限を含む）を修正する。詳細セーブ仕様書は現行の番号・受理範囲と将来分の方針を記載し、過去の移行を履歴として残す。対応表では削除した互換シンボルとテストの順引き／逆引き、基準版とSHAを同期。古いCHANGELOGや履歴の当時の記録は保存し、撤去の履歴を追記する。テスト索引・TODO・開発状況・CHANGELOGを更新し、必要に応じゲームREADMEの移行案内を更新。
- 実装・検証後にゲーム変更の完全SHAを確定させ、資料を同期してGitHubに反映。公開ページの見出しと配信モジュール、公開ブラウザで新規開始・現行保存・非対応データ拒否を確認する。
- 完了条件は、旧形式の専用変換・固定枠定義の実行参照がゼロ、正常な現行データの往復と失敗時の枠保護、回帰テスト・資料・公開整合の確認、ユーザーが自分で削除できる手順の明示。未検証項目や保留した分岐は対象と根拠を引き継ぐ。
