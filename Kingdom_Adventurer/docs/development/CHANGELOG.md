# 変更履歴 — Kingdom Adventurer

開発開始以降の変更の目的・判断・仕様差分を累積記録する。原構想の決定履歴は [history](../history/)、現在の動作は [現行仕様書](../specifications/current/CURRENT_SPECIFICATIONS.md)、実装箇所は [対応表](../architecture/IMPLEMENTATION_MAP.md)、コード差分はGitを正本とする。
日時はJST（UTC+9、Git author date換算）。過去分は2026-11-25にGit履歴・TODO・開発状況から遡及整理した。記録にない理由は推測で補わない。現行仕様IDは後から付与したため初期実装への対応は遡及的である。

## 更新ルール
- 機能追加・仕様変更・不具合修正・リファクタリング・重要な管理資料変更ごとに追記する。既存記録を上書きしない（訂正は訂正記録を追加）。
- 日時、変更種別、目的・理由、変更前後、関連現行仕様ID（必要なら目標仕様ID・TODO ID）、影響範囲、検証結果・未確認事項、対応する確定済みGitコミットの完全SHAを記録する。該当なしは明記する。
- 実装コミットを先に作り、そのSHAを記録して資料更新をコミットする。履歴自身のコミットSHAを自己参照させない。履歴追記だけのコミットを再帰的に記録する必要はない。
- ファイル一覧やコード差分の転載は不要。複数コミットが関係する場合は全て記載する。仕様IDは変更・廃止後も履歴に残す。
- 変更理由が不明なら不明と記録する。検証していない結果を成功と記載しない。
