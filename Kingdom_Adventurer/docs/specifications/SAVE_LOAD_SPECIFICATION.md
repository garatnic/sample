# セーブ・ロード機能仕様書

## 1. 基本方針

- PC・スマートフォンの両方に対応する。
- 現段階ではブラウザ単位でセーブデータを管理する。
- 将来的にはクラウドを利用した端末間のセーブデータ共有に対応する。
- セーブ・ロードによる結果のやり直しを積極的に支援しない。
- リセマラを完全に禁止するための複雑な仕組みは設けない。

## 2. 保存方式

- IndexedDBを使用する。
- セーブ枠は1枠のみとする。
- 手動セーブとオートセーブは同じ保存枠を使用する。
- 保存するたびに既存データを上書きする。
- 内部バックアップおよび世代管理は行わない。
- トランザクションを利用し、保存処理の失敗時には以前の正常なデータを維持する。

## 3. セーブのタイミング

| 条件 | 保存 |
| --- | --- |
| 手動セーブ | する |
| 宿屋での宿泊完了 | する |
| エリア切り替え完了 | する |
| 一定時間の経過 | しない |
| 通常のフィールド移動 | しない |
| メニュー画面の開閉 | しない |
| ブラウザの終了 | しない |

エリア切り替えとは、建物やダンジョンへの出入りなど、実際にゲーム内のエリアが切り替わる処理を指す。

## 4. セーブ禁止条件

以下の状態ではセーブを禁止する。

- 戦闘中
- 死亡中
- エリア切り替え処理中

エリア切り替えが正常に完了した後は保存可能とする。

## 5. 保存対象

プレイヤーおよび世界全体の進行状態を保存する。

- プレイヤーの位置・能力・経験値
- 所持金・所持品・装備
- モンスターの状態
- ギルド依頼・進捗
- 世界の年月日・時刻
- NPCの状態・人間関係
- 地形・建物・資源の状態
- 商店・経済活動
- 国家・領地
- 歴史・イベントの記録
- その他、ゲームの進行状態を復元するために必要な情報

未実装の機能については、実装時に保存対象へ追加する。

## 6. ロード機能

- 最後に保存した状態からゲームを再開する。
- 最後の保存以降の進行は復元しない。
- 保存データの基本的な整合性を確認する。
- プレイヤーと世界の状態を矛盾なく復元する。

### セーブデータの削除

- セーブ画面から、確認のうえでこのブラウザの保存枠を削除できる。
- 削除後も現在のプレイは続行できる。次回の手動セーブやオートセーブで保存枠が新しく作られる。
- 削除を取り消した場合や削除のトランザクションが失敗した場合は、保存枠を維持する。

## 7. 外部バックアップ

- JSON形式による手動エクスポート・インポート機能を設ける。
- 主な目的は外部保管および端末間の手動移行とする。
- バックアップファイルの保管・世代管理はユーザーに委ねる。
- 将来のクラウドセーブでも同じデータ形式を利用できる設計とする。

## 8. セーブデータの容量対策

- 固定情報は可能な限りIDによって参照する。
- 再生成可能な情報は原則として保存しない。
- 地形などは生成シードと変更情報による保存を検討する。
- 画像・音声などの固定素材は保存しない。
- 履歴など、継続的に増加するデータの容量に注意する。
- 必要に応じて圧縮などの対策を追加する。

## 9. プログラム設計・開発方針

- 手動セーブとオートセーブは共通処理を使用する。
- 保存・復元処理と保存先へのアクセス処理を分離する。
- ゲーム本体とは独立したセーブ形式のバージョン番号を設ける。現行の形式5は技能値と技能XPに加え、2国家の在庫・区画建物・住民・資源復活・建築中の仕事を保存する。形式1・2の冒険データを引き継ぎ、国家は保存時刻に初期化する。形式3・4は国家進行を引き継ぐ。形式3では紫峰の新規商店を100Gで初期化する。形式5では共有資源の復活とプレイヤーの採取進捗を保存する。移行は[現行仕様 CUR-SYS-004](current/CURRENT_SPECIFICATIONS.md#cur-sys-004-保存)に従う。
- 将来的な旧形式からのデータ変換に対応できる構造とする。
- 新規ゲーム機能の追加時には、保存・復元処理も併せて対応する。

## 10. 緊急脱出機能との関係

地形への埋没など、プレイヤーが移動不能になる問題については、セーブデータの巻き戻しではなく、別途実装する緊急脱出機能で対応する。
