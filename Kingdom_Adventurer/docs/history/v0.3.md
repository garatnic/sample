では、Kingdom Adventurer 仕様案 v0.3 — NPC・生活AI・世代交代システムを設計しよう。

今回のゲームでは、NPCを単なる会話相手や商店の店員ではなく、世界の中でそれぞれの人生を送る住人として扱いたい。

Kingdom Observerの自律シミュレーションを、冒険者の視点から観察し、交流し、干渉できる仕組みだね。

#### 1. 今回確定した世界構造

| 項目 | 確定仕様 |
| --- | --- |
| 世界生成 | 新規ゲームごとに異なる世界を生成 |
| 地上マップ | シームレスに移動 |
| 屋内・ダンジョン | 別マップ |
| 世界規模 | 複数国家、数十集落、数千人規模 |
| 世界の保存 | 地形・建物・住民・歴史の変化を保存 |

これを前提としてNPCの仕様を検討する。

#### 5. NPCの人間関係

人間関係は、プレイヤーだけでなくNPC同士にも存在させる。

例えば、商人Aと鍛冶師Bが長年取引している場合、商人Aが死亡すると鍛冶師Bの材料調達に影響が出る。

また、NPCが結婚したり、家族を持ったり、別の町へ移住することも考えられる。

ここで重要なのは、どの程度まで人間関係をシミュレーションするか。

#### 6. 死亡と世代交代

NPCが老衰、病気、戦闘などで死亡すると、その人物は世界からいなくなる。

ただし、その影響は残る。

鍛冶師が死亡すれば、店を家族や弟子が継ぐ場合がある。

領主が死亡すれば、後継者争いや相続が発生する。

衛兵が減れば、町の治安が悪化する。

子供が成長すれば、新しい労働者や兵士になる。

この仕組みを採用すると、数十年単位で世界が変化するゲームになる。

一方、NPCの寿命を導入すると、プレイヤーが長期間冒険した際に知り合いが次々と死亡する可能性もある。

そのため、NPCの寿命と時間の進み方はセットで考える必要がある。

#### 7. NPCシステムで決めたい5項目

初期推奨を選択している。ここを確定すれば、生活AIの詳細設計に進める。

なお、個人的には時間の進み方だけは慎重に決めたい。

例えば現実30分でゲーム内1日なら、現実100時間遊んでもゲーム内では約200日しか経過しない。世代交代を体験するには、宿泊・待機・長距離移動などで時間を進める仕組みも必要になる。

この点も含めて、次の段階で生活AIと世代交代を整合させていこう。
