## 決定事項

> Kingdom Adventurer v2.1の人口・出生・死亡・移住仕様として、人口増減：食料・住宅・雇用・治安などに応じて変化。出生：実際のNPCの家族関係から子供が誕生。寿命：種族ごとに寿命・成長速度が異なる。移住：NPCが仕事・生活・安全を考慮して自律移住。集落の発展：人口・資源・経済に応じて自然に拡大・衰退。これらを確定仕様として整理し、次の未確定事項を検討しよう。

## 確認事項と選択肢

<a id="q1"></a>

### 1. 人口の増減要因

- **採用** 食料・住宅・雇用・治安などに連動（推奨）
- **不採用** 地域ごとの固定増減率
- **不採用** ランダムに増減

<a id="q2"></a>

### 2. NPCの出生

- **採用** 実際の家族関係から子供が誕生（推奨）
- **不採用** 人口増加に応じて新NPCを生成

<a id="q3"></a>

### 3. 種族と寿命

- **採用** 種族ごとに寿命・成長速度が異なる（推奨）
- **不採用** 全種族共通の寿命
- **不採用** 個体ごとに寿命が大きくランダム

<a id="q4"></a>

### 4. NPCの移住

- **採用** 仕事・生活・安全を考慮して自律移住（推奨）
- **不採用** 集落間の人口数値だけを移動
- **不採用** 移住なし

<a id="q5"></a>

### 5. 集落の発展と衰退

- **採用** 人口・資源・経済に応じて自然に変化（推奨）
- **不採用** イベントによってのみ発展
- **不採用** 集落規模は固定

Kingdom Adventurer — 仕様案 v2.1

世界シミュレーション仕様の確定／人口・出生・死亡・移住システム

v2.0の5項目を確定仕様に追加する。

これで、Kingdom Adventurerの中核となる**「全NPCが固有の人生を持ち、プレイヤーのいない場所でも世界が動き続ける」**という設計方針が固まった。

今回は、その世界を動かす人口システムを詳しく決めよう。

#### 1. v2.0で確定した仕様

| 項目 | 確定内容 |
| --- | --- |
| 処理方式 | 周辺詳細・近隣簡略・遠方集約の3段階 |
| NPCデータ | 全NPCの個人情報・家族・財産・履歴を保持 |
| 遠方の活動 | 経済・出生・死亡・移住・戦争などが自律進行 |
| 処理負荷 | 端末性能に応じて更新頻度・描画数を自動調整 |
| 歴史保存 | 重要イベントは永続保存、日常行動は要約 |

重要な設計上の区別

遠方のNPCを簡略計算することと、NPCの個人情報を省略することは別。

例えば、遠方の村で暮らす鍛冶師について、毎秒の歩行や作業動作は計算しなくても、年齢・家族・所持金・職業・製作物・死亡などの状態は更新できる。

プレイヤーがその村を訪れたとき、同じ人物が実際に生活しているように表示する。

また、端末性能による自動調整では、原則として世界の出来事の結果を変えず、計算頻度や描画の詳細を調整することを目標とする。

#### 2. 次のテーマ：人口と世代交代

既に確定しているNPCの基本仕様は、結婚、出産、加齢、死亡、転職、移住、財産管理、人間関係の変化など。

今回決めたいのは、それらをどのような規則で発生させるか。

例えば、人口100人の村が豊かになれば自然に人口が増え、食料不足や戦争が起きれば人口が減る。

その変化が、実際のNPCの出生・死亡・移住として記録される仕組みを目指す。

食料・住宅・雇用が充実すると人口が増えやすくなる。

戦争・飢餓・疫病などが起きると人口が減少する。

NPCの出生・死亡は、単なる人口数値の増減ではなく、個人の人生として処理する。

#### 4. NPCの人生と世代交代

NPCのライフサイクル案

誕生親子関係・種族・出生地などを記録する。

成長年齢に応じて行動や能力が変化する。

就職・独立職業を選び、収入を得て生活する。

結婚・家族形成人間関係に応じて家族を作る。

老化・死亡寿命や事故、戦争などによって人生を終える。

相続・歴史への記録財産や地位が引き継がれ、人生の重要な出来事が記録される。

これらは既存仕様を具体化するための構想で、年齢区分や発生条件はまだ未確定。

#### 6. 次に検討すること

人口システムが決まったら、次は経済・生産・交易の詳細に進む。

特に、NPCが実際に働いて商品を生産し、商人が輸送し、店舗で販売するという仕組みをどう成立させるかが重要になる。

人口と経済が連動すれば、プレイヤーが何もしなくても村が都市へ成長したり、戦争によって衰退したりする世界を作れる。

なお、今回のv2.1は設計案であり、実装済みという意味ではない。
