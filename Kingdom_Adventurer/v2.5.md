## 決定事項

> Kingdom Adventurer v2.5の装備・戦利品・アイテム生成仕様として、戦利品：敵が実際に所有していた装備・財産・素材を入手。装備品質：素材・製作者技能・製作条件・個体差で性能決定。ユニーク装備：固有の伝説装備とランダム生成の希少装備が共存。装備条件：能力・技能によって性能が変わり装備自体は柔軟に可能。アイテムの永続性：保管・設置・売買したアイテムは世界に保持。これらを確定仕様として整理し、次の未確定事項を検討しよう。

## 確認事項と選択肢

<a id="q1"></a>

### 1. 敵を倒したときの戦利品

- **採用** 敵が実際に所有していた装備・財産・素材（推奨）
- **不採用** 撃破時にランダム生成
- **不採用** 実際の所持品＋一部ランダム報酬

<a id="q2"></a>

### 2. 装備の品質・性能

- **採用** 素材・製作者技能・製作条件・個体差で決定（推奨）
- **不採用** 主にランダムで決定
- **不採用** 装備種類ごとに性能固定

<a id="q3"></a>

### 3. ユニーク・希少装備

- **採用** 固有の伝説装備＋ランダム生成の希少装備（推奨）
- **不採用** 固有の伝説装備のみ
- **不採用** 希少装備もすべてランダム生成

<a id="q4"></a>

### 4. 装備の使用条件

- **採用** 誰でも装備可能、能力・技能で性能が変化（推奨）
- **不採用** レベル・能力・技能による装備制限
- **不採用** 装備制限も性能補正もなし

<a id="q5"></a>

### 5. アイテムの永続性

- **採用** 保管・設置・売買したアイテムを世界に保持（推奨）
- **不採用** 一定期間で不要アイテムを整理・消滅
- **不採用** 遠方の個別アイテムを統計情報に変換

Kingdom Adventurer — 仕様案 v2.5

戦闘AI仕様の確定／装備・戦利品・アイテム生成

v2.4の5項目を確定仕様に追加する。

今回の決定で、魔物は基本的に敵対するが、戦闘中は状況に応じて判断し、連携・逃走・降伏も行うという戦闘方針が固まった。

#### 1. v2.4で確定した仕様

| 項目 | 確定内容 |
| --- | --- |
| 敵AI | 種族・性格・経験・状況に応じて行動 |
| 敵対判定 | 魔物は基本的にすべて敵対 |
| 逃走・降伏 | NPC・敵とも状況に応じて実行 |
| 集団戦 | 敵も仲間と連携し、役割を分担 |
| 難易度 | 調整可能。ただし敵レベル連動なし |

なお、「魔物は基本的に敵対」と「敵が逃走・降伏する」は両立する。敵対的な魔物でも、戦力差を判断して逃げたり降伏したりできる。

難易度変更によって敵の本来のレベルが変わることもない。

#### 2. 次のテーマ：装備と戦利品

これまでに確定している装備・アイテムの基本仕様は以下のとおり。

武器・防具・アクセサリーなどを装備できる。

アイテムには品質やランダムな能力値、特殊効果がある。

鍛冶・製作・強化・エンチャントが可能。

装備の耐久度はない。

所持品には重量制限がある。

アイテムはNPCの生産・売買・交易にも使われる。

今回決めたいのは、装備の性能がどのように決まり、敵を倒した際に何が手に入り、世界中のアイテムがどう管理されるか。

#### 3. 装備の性能が決まる仕組み

例えば、同じ鉄の剣でも性能が異なる仕組みが考えられる。

鉄の剣の個体差（仮の例）

普通の鉄の剣

攻撃力：12

追加効果なし

優秀な鉄の剣

攻撃力：16

氷属性ダメージ＋3

数値や品質名称は説明用で、確定仕様ではない。

性能には、素材、製作者の技能、品質、エンチャントなどを反映できる。

また、NPCの鍛冶師が実際に製作した剣を、商人が仕入れ、プレイヤーが購入するという経済システムともつながる。

#### 4. 戦利品と世界経済の関係

ここは重要な設計ポイント。

例えば、盗賊を倒したとき、盗賊が装備していた剣や所持していた貨幣を入手できるなら、それらはもともと盗賊が持っていた物として扱える。

一方、ゴブリンを倒すたびに高級な剣や大量の貨幣がランダムに出現すると、これまで確定した実体経済との整合性が崩れる。

そこで、戦利品をどのようなルールで発生させるかを決める必要がある。

#### 5. v2.5で確定したい5項目

#### 6. 技術的に注意したい点

特に⑤のアイテム永続性は、ゲーム全体の保存容量と処理負荷に大きく影響する。

世界中のNPCが何十年も商品を生産し続ければ、アイテム数は膨大になる。

そのため、永続保存を選んだ場合でも、同じ品質・状態の素材をまとめて管理する、消費されたアイテムを記録から整理するなど、世界の整合性を保ちながらデータ量を抑える仕組みが必要になる。

次は、装備・戦利品仕様の確定後、ダンジョン・探索・魔物の巣の詳細設計へ進む。
